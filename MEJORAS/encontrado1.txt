🐛 Bugs
1. Docente creation: race condition entre check de email y RUT
Archivo: 
usuarios.ts:434-456

Se hacen 2 queries separadas (email y RUT) antes del insert. Entre ambas queries otro request podría insertar el mismo email/RUT → unique constraint violation no manejada específicamente.
Mismo bug aplica para 
crearAlumnoAction
.
2. RUT almacenado inconsistentemente
Archivos: 
usuarios.ts
, 
auth.ts

A veces se guarda normalizarRut() (sin puntos), a veces formatearRut() (con puntos). El login busca con 
OR(rut = normalizado, rut = formateado)
 para compensar, pero si se crean alumnos por importación CSV y el formato no coincide, puede fallar la autenticación.
La tabla usuarios tiene constraint uniq(rut, rol) pero si el mismo RUT se guarda con formato distinto, el unique no lo detecta.
3. Sesión de 1 hora demasiado corta
Archivo: 
auth.ts:229

maxAge: 60 * 60 = 1 hora. Un alumno o docente trabajando más de 1 hora pierde la sesión sin warning. No hay mecanismo de extensión automática (el updateAge: 15 * 60 solo funciona si hay actividad).
4. clases sin filtro eliminadoAt en docente
Archivo: 
docente.ts:168

listarClasesDocente
 no filtra isNull(clases.eliminadoAt), así que clases eliminadas siguen apareciendo en la lista del docente.
5. Import route no aplica rate limiting
Archivo: 
import-alumnos/route.ts

La ruta /api/internal/import-alumnos es bypassed por el middleware (línea 143-153 de 
middleware.ts
 permite api/internal/* sin rate limit).
Un admin con sesión podría enviar muchos archivos grandes sin límite.
6. Contraseña alumno derivada es predecible
Archivo: 
auth.ts:329

Fórmula: ${rutSalt}${rut}${userId}. Si alguien obtiene el RUT_SALT y el userId (que es un UUID visible en logs/URL), puede generar la contraseña del alumno.
El alumno no tiene manera de cambiar su contraseña.
7. searchParams tipado como sync pero es async en Next.js 14+
Archivo: 
alumno/solicitudes/page.tsx:48-52

searchParams ahora es Promise<> en Next.js 14.2+. Esto puede causar errores en producción.
8. Email send silencia todos los errores
Varios archivos: usuarios.ts:519, solicitudes-documentos.ts:147

sendEmail(...).catch(() => {}) oculta fallos de envío. Si el servidor SMTP no funciona, nadie se entera.

Múltiples archivos: asignaturas.ts:457, clases.ts:436, matriculas.ts:547, etc.

En Next.js,

📋 Secciones que FALTAN Completamente
64. Sección "Finanzas" (admin)
Schema existe: tabla finanzas con tipo (ingreso/gasto), monto, categoría, comprobante URL, vinculación a asignatura.
Falta: Página /admin/finanzas, actions CRUD, dashboard con ingresos vs gastos, gráficos.

65. Sección "Certificados" (admin + alumno)
Schema existe: tabla certificados con código único, QR, snapshot de datos, tipo (alumno_regular, término_curso).

66. Sección "Evaluaciones" completa (admin + docente + alumno)
Schema existe: tablas evaluaciones, preguntas, respuestasFormulario, notas.

67. Sección "Material Didáctico" (docente + alumno)
Schema existe: tabla material con nombre, storagePath, hash MD5, tamaño.
Falta: Upload de archivos por docente, descarga por alumno, gestión de materiales por clase.

68. Sección "Observaciones" visible para alumno

69. Sección "Auditoría / Log de Actividad" (admin)

70. Sección "Reportes" (admin)

Reporte financiero mensual
Reporte de matrículas activas vs inactivas
71. Página de "Mi Perfil" (todos los roles)
Falta: Página donde el usuario pueda ver sus datos, cambiar su foto de perfil (campo avatarUrl existe), cambiar contraseña.
72. Sección "Calendario" (docente + alumno)
Falta: Vista de calendario con clases programadas. La data ya existe en clases.fecha y clases.horaInicio.
73. Sección "Mensajes / Comunicados" (todos)

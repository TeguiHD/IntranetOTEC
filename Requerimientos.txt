## PRINCIPIO DE INMUTABILIDAD — REGLA ABSOLUTA

**En este sistema NUNCA se borra nada de la base de datos.**

Todo registro que el usuario "elimine" o "desactive" simplemente cambia de
estado o recibe una marca de tiempo. Sigue existiendo en la DB. Los datos
son permanentes; solo cambia su visibilidad en la interfaz.

### Implementación por entidad

| Entidad | Mecanismo | Campo |
|---------|-----------|-------|
| `usuarios` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `asignaturas` | cambio de estado | `estado: 'archivado'` (estado final) |
| `matriculas` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `clases` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `material` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `evaluaciones` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `notas` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `finanzas` | soft-delete | `eliminadoAt timestamptz`, `eliminadoPor uuid` |
| `certificados` | cambio de estado | `valido: false` (nunca borrar) |

### Convención de queries — OBLIGATORIA

Toda query a una tabla con soft-delete DEBE filtrar registros activos:

```typescript
// ✅ CORRECTO — siempre filtrar
db.select().from(material).where(isNull(material.eliminadoAt))

// ❌ INCORRECTO — nunca omitir el filtro
db.select().from(material)
```

Crear un helper reutilizable en `src/db/filters.ts`:
```typescript
import { isNull } from 'drizzle-orm';

// Usar en cualquier tabla que tenga eliminadoAt
export const activo = <T extends { eliminadoAt: unknown }>(tabla: T) =>
  isNull(tabla.eliminadoAt);
```

### Sin CASCADE en claves foráneas

Ninguna relación usará `onDelete: 'cascade'`. Si una clase se "elimina",
su material queda en DB con `eliminadoAt` propio. Cada entidad gestiona
su propio ciclo de vida independientemente.

### En la interfaz

- Los registros con `eliminadoAt IS NOT NULL` no aparecen en listados normales
- El admin puede ver registros "eliminados" con un toggle "Mostrar inactivos"
- La acción en UI siempre dice "Desactivar" o "Archivar", nunca "Eliminar"
- Antes de desactivar: modal de confirmación con texto requerido

### Tablas históricas — eliminadas

Las tablas `asistencia_historico` y `notas_historico` del diseño original
**no son necesarias**. El "Cerrar Ciclo" simplemente cambia el estado de la
asignatura a `finalizado` y congela la escritura vía permisos. Los datos
originales permanecen intactos en sus tablas.

## CONTEXTO DEL SISTEMA

Intranet educativa para un OTEC (Organismo Técnico de Capacitación) chileno.
NO es un LMS público. Es una intranet administrativa con aula virtual integrada.

**Tres roles con permisos granulares:**
- `admin` — Director. Crea asignaturas, matricula alumnos, gestiona docentes y finanzas
- `docente` — Profesor. Gestiona sus clases, asistencia, material y evaluaciones
- `alumno` — Estudiante. Ve sus clases, notas, material y descarga certificados

**Jerarquía de entidades clave:**
```
Asignatura (materia)
├── Docente asignado (1)
├── Alumnos matriculados (N) → tabla matriculas
├── Clases / Sesiones (N)
│   ├── Grabación de video (YouTube / Vimeo / Drive / directo)
│   ├── Material PDF por clase
│   └── Registro de asistencia por clase
└── Evaluaciones
    ├── Formulario online (preguntas + respuestas)
    ├── Tarea (el alumno sube un archivo)
    └── Examen (el docente ingresa nota directamente)
```

**Particularidades chilenas:**
- Los alumnos se identifican con RUT (no email). El login de alumno es
  solo con RUT — sin contraseña visible. El sistema deriva la contraseña
  internamente: `bcrypt(RUT_SALT + rutLimpio)`.
- El RUT se valida con el algoritmo Módulo 11.
- El admin crea a los alumnos — el alumno nunca se registra solo.

## AUTENTICACIÓN (Auth.js v5)

Archivo: `src/auth.ts`

Dos providers de Credentials:

**1. `alumno-rut`** — El alumno escribe solo su RUT (formato `12.345.678-9`).
El backend busca al usuario por RUT, luego verifica:
`bcrypt.compare(process.env.RUT_SALT + rutLimpio, usuario.password)`

**2. `staff-credentials`** — Docente y Admin usan email + contraseña normal.

En ambos casos el callback `jwt` agrega `token.rol` y el callback `session`
expone `session.user.id` + `session.user.rol`.

Configuración de sesión: `strategy: 'jwt'`, `maxAge: 3600` (1 hora),
`updateAge: 900` (renovar cada 15 min).

Páginas custom: `signIn: '/login'`, `error: '/login'`.

## VALIDACIÓN DE RUT CHILENO

Archivo: `src/lib/rut.ts`

```typescript
export function validarRut(rut: string): boolean {
  const cleaned = rut.replace(/[^0-9kK]/g, '').toUpperCase();
  if (cleaned.length < 2) return false;
  const dv = cleaned.slice(-1);
  const body = cleaned.slice(0, -1);
  let sum = 0, mul = 2;
  for (let i = body.length - 1; i >= 0; i--) {
    sum += parseInt(body[i]) * mul;
    mul = mul < 7 ? mul + 1 : 2;
  }
  const exp = 11 - (sum % 11);
  const dvExp = exp === 11 ? '0' : exp === 10 ? 'K' : String(exp);
  return dv === dvExp;
}

export function formatRut(rut: string): string {
  const cleaned = rut.replace(/[^0-9kK]/g, '').toUpperCase();
  const dv = cleaned.slice(-1);
  const body = cleaned.slice(0, -1).replace(/\B(?=(\d{3})+(?!\d))/g, '.');
  return `${body}-${dv}`;
}
```

El componente `<RutInput />` usa esta función para validar en tiempo real,
aplicar el formato automático y mostrar feedback visual (borde verde/rojo).

## STORAGE DE ARCHIVOS

Archivo: `src/lib/storage.ts`

- **Desarrollo:** filesystem local en `/uploads/` — usar `fs.writeFile`
- **Producción:** MinIO (S3-compatible, self-hosted)

La interfaz expone solo dos funciones:
- `uploadFile(bucket, path, buffer, contentType): Promise<string>`
- `getPresignedUrl(bucket, path): Promise<string>` (URL firmada, 1 hora)

Buckets: `material` (PDFs de clases), `entregas` (trabajos de alumnos).

El MD5 del archivo se calcula **en el cliente** antes de subir para detectar
duplicados. El hash se envía junto con el upload y se verifica contra
`material.hash_md5` antes de insertar.

## REALTIME (SSE + PostgreSQL LISTEN/NOTIFY)

Archivo: `src/app/api/sse/material/route.ts`

PostgreSQL trigger en la tabla `material`:
```sql
CREATE OR REPLACE FUNCTION notify_material_nuevo()
RETURNS TRIGGER AS $$
BEGIN
  PERFORM pg_notify('material_nuevo', row_to_json(NEW)::text);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER on_material_insert
  AFTER INSERT ON material
  FOR EACH ROW EXECUTE FUNCTION notify_material_nuevo();
```

El Route Handler hace `LISTEN material_nuevo` con un cliente `pg` dedicado
y escribe al stream SSE en cada notificación.

Hook del cliente: `src/hooks/useSSE.ts` — consume el endpoint y expone
el último evento. Dispara un toast con `sonner` cuando llega material nuevo.

## RESTRICCIONES ABSOLUTAS (nunca romper)

1. **Base de datos:** solo PostgreSQL — no SQLite, no MongoDB, no archivos JSON
2. **ORM:** solo Drizzle — no Prisma, no TypeORM, no raw SQL sin tipos
3. **Autenticación:** solo Auth.js v5 — no implementar JWT manual
4. **PDFs:** siempre generados en cliente con `@react-pdf/renderer` — nunca en servidor
5. **PDFs:** siempre visualizados inline con `react-pdf` — nunca abrir nueva pestaña
6. **Storage:** MinIO o filesystem — nunca base64 en la base de datos
7. **Acciones destructivas:** siempre requieren confirmación escrita explícita
8. **`datosSnapshot` del certificado:** inmutable una vez emitido — nunca actualizar
9. **`RUT_SALT`:** nunca exponer al cliente bajo ninguna circunstancia
10. **Queries en listados:** siempre paginadas, máximo 50 registros por página
11. **TypeScript:** modo strict activado — no usar `any` sin justificación explícita
12. **NUNCA usar DELETE en PostgreSQL** — toda "eliminación" es un UPDATE que
    asigna `eliminadoAt = now()` y `eliminadoPor = userId`. Sin excepciones.
13. **Sin `onDelete: 'cascade'`** en ninguna relación del schema Drizzle.
    Cada tabla gestiona su propio ciclo de vida.
14. **Toda query debe filtrar** `WHERE eliminado_at IS NULL` en tablas con
    soft-delete, excepto en vistas de auditoría del admin.
15. **El archivo físico en storage nunca se borra** aunque el registro de
    `material` sea soft-deleted. El storage es append-only.

## PRINCIPIO DE INMUTABILIDAD — REGLA ABSOLUTA

**En este sistema NUNCA se ejecuta DELETE en la base de datos.**

Todo registro que el usuario "elimine" o "desactive" simplemente cambia de
estado o recibe una marca de tiempo. Sigue existiendo en la DB. Los datos
son permanentes; solo cambia su visibilidad en la interfaz.

### Implementación por entidad

| Entidad | Mecanismo | Campos |
|---------|-----------|--------|
| `usuarios` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `asignaturas` | cambio de estado | `estado: 'archivado'` (estado final) |
| `matriculas` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `clases` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `material` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `evaluaciones` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `notas` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `finanzas` | soft-delete | `eliminado_at timestamptz`, `eliminado_por uuid` |
| `certificados` | cambio de estado | `valido: false` (nunca borrar) |
| `asistencia` | corrección | UPDATE del campo `estado` — no soft-delete |
| `audit_logs` | inmutable | NUNCA se modifica — solo INSERT |

### Convención de queries — OBLIGATORIA

```typescript
// src/db/filters.ts
import { isNull } from 'drizzle-orm';

export const activo = <T extends { eliminadoAt: unknown }>(t: T) =>
  isNull(t.eliminadoAt);

// ✅ CORRECTO
db.select().from(material).where(activo(material))

// ❌ INCORRECTO — nunca omitir el filtro
db.select().from(material)
```

### Sin CASCADE en claves foráneas

Ninguna FK usará `onDelete: 'cascade'`. Cada entidad gestiona su propio
ciclo de vida con soft-delete independiente.

### En la interfaz

- Registros con `eliminado_at IS NOT NULL` no aparecen en listados normales
- El admin tiene toggle "Mostrar inactivos" en todas las tablas
- La acción en UI dice "Desactivar" o "Archivar", nunca "Eliminar"
- Antes de desactivar: modal con texto de confirmación requerido + audit log
- Sin tablas históricas: "Cerrar Ciclo" solo cambia `estado` a `finalizado`.
  Los datos permanecen intactos en sus tablas originales.

## ESQUEMA DE BASE DE DATOS (Drizzle ORM)

Archivo: `src/db/schema.ts`

**Regla global de timestamps:** Todos los campos de fecha/hora usan
`{ withTimezone: true }` (timestamptz). Chile opera en `America/Santiago`.
El shorthand `tstz()` se define una vez y se reutiliza.

```typescript
import {
  pgTable, pgEnum, uuid, text, integer, numeric,
  boolean, date, timestamp, time, jsonb, unique, index
} from 'drizzle-orm/pg-core';
import { sql } from 'drizzle-orm';

// Shorthand timestamptz reutilizable
const tstz = (name: string) => timestamp(name, { withTimezone: true });

// ── ENUMS ─────────────────────────────────────────────────────────────
export const rolEnum         = pgEnum('rol',         ['admin','docente','alumno']);
export const estadoAsigEnum  = pgEnum('estado_asig', ['borrador','activo','finalizado','archivado']);
export const estadoPagoEnum  = pgEnum('estado_pago', ['pendiente','pagado','mora','becado']);
export const estadoAsistEnum = pgEnum('estado_asist',['presente','ausente','tardanza','justificado']);
export const tipoEvalEnum    = pgEnum('tipo_eval',   ['formulario','tarea','examen','proyecto']);
export const tipoPregEnum    = pgEnum('tipo_preg',   ['opcion_multiple','verdadero_falso',
                                                      'respuesta_corta','desarrollo']);
export const tipoCertEnum    = pgEnum('tipo_cert',   ['alumno_regular','termino_curso']);
export const tipoFinEnum     = pgEnum('tipo_fin',    ['ingreso','gasto']);
export const tipoVideoEnum   = pgEnum('tipo_video',  ['youtube','vimeo','drive','directo']);
export const auditAccionEnum = pgEnum('audit_accion', [
  'login_ok','login_fail','logout',
  'crear','editar','desactivar','archivar',
  'cerrar_ciclo','emitir_certificado','invalidar_certificado',
  'subir_material','exportar_excel',
  'cambiar_nota','registrar_asistencia',
]);

// ── USUARIOS ──────────────────────────────────────────────────────────
export const usuarios = pgTable('usuarios', {
  id:           uuid('id').primaryKey().defaultRandom(),
  rut:          text('rut').unique(),
  nombre:       text('nombre').notNull(),
  apellido:     text('apellido').notNull(),
  email:        text('email').unique(),
  password:     text('password'),              // bcrypt(SALT + rut + id), cost 12
  rol:          rolEnum('rol').notNull(),
  avatarUrl:    text('avatar_url'),
  activo:       boolean('activo').default(true),
  eliminadoAt:  tstz('eliminado_at'),          // null = activo
  eliminadoPor: uuid('eliminado_por'),
  createdAt:    tstz('created_at').defaultNow(),
  updatedAt:    tstz('updated_at').defaultNow(),
});

// ── ASIGNATURAS ───────────────────────────────────────────────────────
export const asignaturas = pgTable('asignaturas', {
  id:            uuid('id').primaryKey().defaultRandom(),
```

## SEGURIDAD — IMPLEMENTACIÓN COMPLETA

### Modelo de amenazas (STRIDE · OWASP 2025 · MITRE ATT&CK)

| Amenaza | Vector | Control |
|---------|--------|---------|
| Broken Access Control (A01) | Acceso a ruta de otro rol | Middleware + verificación en Server Action |
| Cryptographic Failures (A02) | Passwords débiles | bcrypt cost 12 + hash único por usuario (salt + id) |
| Injection / SQLi (A03) | Input malicioso a queries | Drizzle ORM parameterized — imposible SQL raw accidental |
| XSS (A03) | Input → render HTML | DOMPurify en cliente + sanitizeText() en servidor |
| SSTI (A03) | Template injection | Sin motores de template server-side; solo JSX compilado |
| Insecure Design (A04) | Lógica bypasseable | Zod en cliente Y servidor, doble check de rol |
| RCE (A08) | Código desde input | Sin eval(), Function(), child_process con input de usuario |
| SSRF | Fetch de URLs internas | Whitelist de dominios en sanitizeVideoUrl() |
| DDoS / Brute Force (A07) | Flood de requests | Rate limit pg: 5 intentos login/min, 60 req/min default |
| Session Hijacking (T1539) | Robo de JWT | httpOnly + SameSite=Strict + Secure + maxAge 1h |
| Path Traversal | `/api/files/../../etc` | sanitizePath() + whitelist de buckets |
| CORS mal configurado | Requests cross-origin | Origen = solo NEXT_PUBLIC_BASE_URL |
| Clickjacking | iframe embed malicioso | X-Frame-Options: DENY + CSP frame-ancestors 'none' |

```typescript
import DOMPurify from 'isomorphic-dompurify';
import validator from 'validator';

// Texto libre (descripciones, observaciones) — quita TODO HTML/JS
export const sanitizeText = (s: string): string =>
  DOMPurify.sanitize(s, { ALLOWED_TAGS: [], ALLOWED_ATTR: [] }).trim();

// Paths de archivo — previene path traversal
export const sanitizePath = (s: string): string => {
  const clean = s.replace(/\.\./g, '').replace(/[^a-zA-Z0-9\/\-_.]/g, '');
  if (clean.includes('..')) throw new Error('Invalid path');
  return clean;
};

// URLs de video — whitelist estricta de dominios permitidos
const ALLOWED_VIDEO = ['youtube.com','youtu.be','vimeo.com','drive.google.com'];

export const sanitizeVideoUrl = (url: string): boolean => {
  if (!validator.isURL(url, { require_protocol: true })) return false;
  const { hostname } = new URL(url);
  return ALLOWED_VIDEO.some(d => hostname.endsWith(d));
};
```

Cada Server Action que recibe texto libre **debe** pasar por `sanitizeText`.

```typescript
  const session = await auth();
```

## VALIDACIÓN DE RUT CHILENO

Archivo: `src/lib/rut.ts`

```typescript
export function validarRut(rut: string): boolean {
  const cleaned = rut.replace(/[^0-9kK]/g, '').toUpperCase();
  if (cleaned.length < 2) return false;
  const dv   = cleaned.slice(-1);
  const body = cleaned.slice(0, -1);
  let sum = 0, mul = 2;
  for (let i = body.length - 1; i >= 0; i--) {
    sum += parseInt(body[i]) * mul;
    mul  = mul < 7 ? mul + 1 : 2;
  }
  const exp = 11 - (sum % 11);
  return dv === (exp === 11 ? '0' : exp === 10 ? 'K' : String(exp));
}

export function formatRut(rut: string): string {
  const c  = rut.replace(/[^0-9kK]/g, '').toUpperCase();
  const dv = c.slice(-1);
  const b  = c.slice(0, -1).replace(/\B(?=(\d{3})+(?!\d))/g, '.');
  return `${b}-${dv}`;
}

// Solo en Server Action — nunca en cliente
export async function derivarPasswordAlumno(rut: string, id: string): Promise<string> {
  return bcrypt.hash(process.env.RUT_SALT! + rut + id, 12);
}
```

## RESTRICCIONES ABSOLUTAS (nunca romper)

1. Solo PostgreSQL 16 — no SQLite, MongoDB, archivos JSON
2. Solo Drizzle ORM — no Prisma, TypeORM, raw SQL sin tipos
3. Solo Auth.js v5 — no JWT manual
4. PDFs generados en cliente con `@react-pdf/renderer` — nunca en servidor
5. PDFs visualizados inline con `react-pdf` — nunca nueva pestaña
6. Storage: MinIO o filesystem — nunca base64 en DB, nunca `deleteFile()`
7. Acciones destructivas: confirmación escrita + audit log
8. `datosSnapshot` del certificado: inmutable al emitir
9. `RUT_SALT`: nunca al cliente
10. Queries listados: paginadas, máximo 50 registros
11. TypeScript strict: no `any` sin justificación documentada
12. **NUNCA `DELETE` en PostgreSQL** — soft-delete siempre
13. Sin `onDelete: 'cascade'` en ninguna FK
14. Toda query filtra `WHERE eliminado_at IS NULL` (excepto auditoría)
15. Storage append-only — el archivo físico nunca se borra
16. **`timestamp` siempre `{ withTimezone: true }`** — sin excepciones
17. **Índice parcial obligatorio** en tablas con soft-delete y listados frecuentes
18. **bcrypt cost factor 12 mínimo** — no reducir
19. **Hash alumno incluye `usuario.id`**: `bcrypt(SALT + rut + id)`
20. **Rate limit antes de auth** en middleware — orden inamovible
21. **`registrarAudit()` en toda acción crítica** — lista en sección Seguridad
22. **`inputMode` declarado en todo `<input>`** — UX móvil obligatorio
23. **`100dvh`** en lugar de `100vh` en todo layout
24. **`sanitizeVideoUrl()`** antes de renderizar cualquier iframe
25. **`eval()`, `Function()`, `child_process` con input de usuario:** prohibidos
